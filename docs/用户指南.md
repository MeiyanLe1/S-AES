# S-AES 加解密实验程序 · 用户指南

> 面向使用者的上手说明。算法细节与接口请见《开发手册》，测试情况见《测试过关报告》。

## 1. 简介

本程序是“信息安全导论”课程实验作业，依据教材附录 D（简化 AES）实现 S-AES 加解密，覆盖五个关卡：

| 关卡 | 内容 | 对应界面 |
| --- | --- | --- |
| 第 1 关 | 基本加解密（16 bit 明文 / 16 bit 密钥） | 页面① |
| 第 2 关 | 交叉测试（与同学比对测试向量） | 页面① 底部 |
| 第 3 关 | 字符串加解密（按 2 字节分组，支持中文） | 页面② |
| 第 4 关 | 多重加密（双重 / 三重，32 bit 密钥）与中间相遇攻击 | 页面③、④ |
| 第 5 关 | CBC 工作模式与密文篡改分析 | 页面⑤ |

程序为 **Python + PyQt5** 桌面应用；算法层（`s_aes/core.py`、`modes.py`、`multi.py`）不依赖 GUI，可单独做单元测试或命令行自测。

## 2. 环境要求与安装

- Python 3.8 及以上（开发环境为 3.11）。
- 仅 GUI 需要第三方库 PyQt5；算法与测试只用标准库。

```bash
# 安装依赖（只需 PyQt5）
pip install -r requirements.txt
```

## 3. 启动方式

```bash
# 1) 启动图形界面（需要 PyQt5）
python main.py

# 2) 只跑算法自测（不需要 PyQt5，可在无界面环境验证算法）
python main.py --selftest

# 3) 运行单元测试（共 21 项）
python -m unittest discover -s tests -v
```

> 若提示找不到 PyQt5：执行 `pip install PyQt5`；若只想验证算法，用 `python main.py --selftest`。

## 4. 五个关卡操作说明

### 第 1 关 · 基本加解密（页面①）

- 在输入框填写 **16 bit 明文** 与 **16 bit 密钥**。
- 输入支持：十六进制（可带 `0x`、空格，如 `6F6B`、`0x6F 6B`）或 **16 位二进制**。
- 下方「位点阵」可**逐位点击翻转**，方便观察比特级变化。
- 界面实时显示密钥扩展得到的轮密钥 `K0 / K1 / K2`。
- “轮函数中间状态”表逐行列出每次变换后的 16 bit 状态，便于核对算路。
- 点击「加密 / 解密」得到结果，可反向还原。

**示例**：`明文 = 6F6B`，`密钥 = A73B` → 密文 `0738`（解密可还原 `6F6B`）。

### 第 2 关 · 交叉测试（页面① 底部）

- 页面底部给出与教材一致的**只读信息**：S 盒、列混淆矩阵与其逆矩阵、参考向量。
- 点击「复制测试向量」可把明文、密钥、密文、轮密钥、S 盒、矩阵一并复制到剪贴板，
  发给同组同学即可核对密文是否一致（算法层与平台无关）。
- 用于验证你的实现与教材 / 他人实现完全一致。

### 第 3 关 · 字符串加解密（页面②）

- 明文按 **2 字节（16 bit）** 分组逐组加密；采用 UTF-8 编码，因此**中文也能正确往返**。
- 填充采用 PKCS#7 变体（2 字节分组）：缺 1 字节补 `0x01`，缺 2 字节补一整组 `0x02 0x02`。
- 密文可切换「十六进制 / 字符视图」；字符视图中非可打印字节显示为 `·`（密文通常是乱码）。
- 下方表格列出每组明文与密文的 16 bit 值。

### 第 4 关 · 多重加密（页面③）

- 密钥长度扩展为 **32 bit**：`Key = K1 ‖ K2`（高 16 位 K1，低 16 位 K2），界面自动拆分展示。
- **双重加密**：`C = E_K2(E_K1(P))`，解密 `P = D_K1(D_K2(C))`。
- **三重加密（EDE，K3 = K1）**：`C = E_K1(D_K2(E_K1(P)))`；当 `K1 = K2` 时自动退化为单次 S-AES（与 3DES 思路一致）。
- “运算流程”把每一步中间值（E_K1 / D_K2 等）横向展示。

### 第 4.2 关 · 中间相遇攻击（页面④）

- 原理：双重加密下中间值 `M = E_K1(P) = D_K2(C)`。
  先枚举全部 2¹⁶ 个 K1 建立「M → K1」索引表，再枚举 2¹⁶ 个 K2 计算 `D_K2(C)` 查表；
  复杂度由 2³² 降到 2×2¹⁶。
- 界面支持添加多组明密文对（或一键生成样例），后台线程执行，显示进度、耗时、建表规模与候选密钥表。
- 候选密钥会用**全部**明密文对复核。只给 1～2 组对时可能出现多组等价密钥（碰撞），**多加几组即可唯一确定**。

### 第 5 关 · CBC 工作模式（页面⑤）

- IV 为 16 bit，可随机生成或手动填写，界面显式展示（IV 无需保密，但必须双方共享）。
- 加密：`C_i = E_K(P_i ⊕ C_{i-1})`，`C_0` 的前一组即 IV；明文按 2 字节分组，末组填充。
- 密文按分组卡片展示，点击任一分组后：
  - 「应用篡改」改写为指定十六进制值（等价于替换分组）；
  - 「随机翻转一位」做单比特篡改，观察错误传播；
  - 「恢复原密文」还原。
- 下方并排对比「原始明文」与「篡改后解密结果」：被改分组标红，其后一组标黄。
  可直接看到：**被改动的分组明文整组变为乱码，下一分组只有相同比特位翻转，其余分组不受影响**。

## 5. 常见问题（FAQ）

1. **提示找不到 PyQt5**：执行 `pip install PyQt5`；只想验证算法可运行 `python main.py --selftest`。
2. **输入长度不对**：单分组要求恰好 16 bit（4 位十六进制或 16 位二进制）；第 4 关密钥为 32 bit（8 位十六进制）。
3. **密文显示为乱码**：正常现象，密文分组通常不是可打印字符，界面同时提供十六进制视图。
4. **解密提示填充校验失败**：说明密文被改动过（例如第 5 关的篡改演示），填充规则无法还原原始长度。
5. **中间相遇攻击得到多组候选密钥**：见第 4.2 关说明，增加明密文对即可筛选唯一密钥。
