# S-AES 加解密实验程序

“信息安全导论”课程实验作业：依据教材附录 D（简化 AES）实现 S-AES 加解密程序，覆盖五个关卡：
基本测试、交叉测试、字符串扩展、多重加密（含中间相遇攻击）与 CBC 工作模式。

程序为 Python + PyQt5 桌面应用，界面分五个页面，算法层不依赖 GUI，可单独做单元测试。

## 1. 环境与运行

```bash
# 1) 安装赖（仅需要 PyQt5，算法与测试只用标准库）
pip install -r requirements.txt

# 2) 启动图形界面
python main.py

# 3) 只跑算法自测（不需要 PyQt5）
python main.py --selftest
```

- 开发环境：Windows + Python 3.11（PyQt5 5.15 及以上）。
- 所有路径使用相对导入，工作目录包含中文不影响运行。

## 3. 关卡与界面功能

### 第 1 关 · 基本测试（页面①）

- 输入 16 bit 明文与 16 bit 密钥，输出 16 bit 密文；支持反向解密。
- 输入框接受十六进制（可带 `0x`、空格）或 16 位二进制；下方「位点阵」可逐位点击翻转。
- 实时显示密钥扩展得到的轮密钥 `K0 / K1 / K2`。
- “轮函数中间状态”表逐行列出每次变换后的 16 bit 状态，方便核对算路。

### 第 2 关 · 交叉测试（页面①下方）

页面底部给出与教材一致的只读信息：S 盒、列混淆矩阵与其逆矩阵、参考向量；
「复制测试向量」把明文、密钥、密文、轮密钥、S 盒、矩阵一并复制到剪贴板，
发给同组同学即可核对密文是否一致（算法层与平台无关）。

### 第 3 关 · 字符串加解密（页面②）

- 明文按 2 字节（16 bit）分组，逐组加密；UTF-8 编码，因此中文也能正确往返。
- 填充采用 PKCS#7 变体（2 字节分组）：缺 1 字节补 `0x01`，缺 2 字节补一整组 `0x02 0x02`。
- 密文可切换「十六进制 / 字符视图」；字符视图中非可打印字节显示为 `·`（密文通常是乱码）。
- 下方表格列出每组明文与密文的 16 bit 值。

### 第 4 关 · 多重加密（页面③）

- 密钥长度扩展为 32 bit：`Key = K1 ‖ K2`（高 16 位 K1，低 16 位 K2），界面自动拆分展示。
- **双重加密**：`C = E_K2(E_K1(P))`，解密 `P = D_K1(D_K2(C))`。
- **三重加密（选用 32 bit 密钥方案，K3 = K1）**：`C = E_K1(D_K2(E_K1(P)))`，
  即“加密—解密—加密”（EDE）；当 K1 = K2 时自动退化为单次 S-AES，与 3-DES 的思路一致。
- “运算流程”把每一步的输出（E_K1 / D_K2 的中间值）横向展示。

### 第 4.2 关 · 中间相遇攻击（页面④）

- 原理：双重加密下中间值 `M = E_K1(P) = D_K2(C)`。
  先枚举全部 2^16 个 K1 建立「M → K1」索引表，再枚举 2^16 个 K2 计算 `D_K2(C)` 查表；
  复杂度由 2^32 降到 2×2^16。
- 界面支持添加多组明密文对（或一键生成样例），后台线程执行，显示进度、耗时、建表规模与候选密钥表。
- 候选密钥会用**全部**明密文对复核。注意：只给 1～2 组对时可能出现多组等价密钥
  （2^32 个密钥映射到 2^32 种“两组明密文组合”，本来就会碰撞），多加几组即可唯一确定。

### 第 5 关 · CBC 工作模式（页面⑤）

- IV 为 16 bit，可随机生成或手动填写，界面显式展示（IV 无需保密，但必须双方共享）。
- 加密：`C_i = E_K(P_i ⊕ C_{i-1})`，`C_0` 的前一组即 IV；明文按 2 字节分组，末组填充。
- 密文按分组卡片展示，点击任一分组后：
  - 「应用篡改」把它改写为指定十六进制值（等价于替换分组）；
  - 「随机翻转一位」做单比特篡改，观察错误传播；
  - 「恢复原密文」还原。
- 下方并排对比「原始明文」与「篡改后解密结果」：被改分组标红，其后一组标黄。
  可以直接看到：**被改动的分组明文整组变为乱码，下一分组只有相同比特位翻转，其余分组不受影响**。

## 4. 算法要点（与附录 D 一致）

| 项目        | 取值                                                    |
| --------- | ----------------------------------------------------- |
| 分组 / 密钥   | 16 bit / 16 bit（多重加密 32 bit），共 2 轮                    |
| S 盒       | `9 4 A B / D 1 8 5 / 6 2 0 3 / C E F 7`               |
| 逆 S 盒     | `A 5 9 B / 1 7 8 F / 4 C 3 D / E 6 0 2`               |
| 列混淆 / 逆矩阵 | `[[1,4],[4,1]]` / `[[9,2],[2,9]]`，GF(2^4) 模 `x^4+x+1` |
| 轮常数       | `RCON1 = 0x80`，`RCON2 = 0x30`                         |
| 加密        | `A_K0 → [NS → SR → MC → A_K1] → [NS → SR → A_K2]`     |
| 解密        | `A_K2 → ISR → INS → A_K1 → IMC → ISR → INS → A_K0`    |

状态按列主序放置：`(s00, s10, s01, s11)` 对应 16 bit 数的高 4 位到低 4 位，
因此行移位等价于交换第 2、4 个半字节（`state[1] ↔ state[3]`）。

## 6. 代码规范说明

- 命名：变量/函数用 `snake_case`，类用 `PascalCase`，名字表达用途（如 `expand_key`、`tamper_analysis`）。
- 注释：只解释算法意图与不直观之处（GF(2⁴) 乘法、填充规则、行移位下标、攻击建表逻辑），不逐行翻译代码。

  页面只做输入校验与渲染；重复控件抽成 `widgets.py` 中的可复用类。

## 7. 常见问题

1. **提示找不到 PyQt5**：执行 `pip install PyQt5`；只想验证算法可运行 `python main.py --selftest`。
2. **输入长度不对**：程序要求恰好 16 bit（4 位十六进制或 16 位二进制）；第 4 关密钥为 32 bit（8 位十六进制）。
3. **密文显示为乱码**：正常现象，密文分组通常不是可打印字符，界面同时提供十六进制视图。
4. **解密提示填充校验失败**：说明密文被改动过（例如第 5 关的篡改演示），填充规则无法还原原始长度。
5. **中间相遇攻击得到多组候选密钥**：见第 4.2 关说明，增加明密文对即可筛选。
